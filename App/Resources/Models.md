# Dropped models

This note sits beside `Models/`, not inside it. Xcode copies that folder into
the app as a whole, so a readme or a placeholder in there would ship with the
game.

Drop a `<asset name>.usdz` file into `Models/`. The names are the `AssetName`
list in `docs/asset-brief.md` (for example `gondola_shelf.usdz`). The app loads
the file instead of the code-built shape at the next build, with no code change.

Five files are the exception and are sourced, not generated: `parked_car_hatchback`,
`parked_car_saloon`, `parked_car_van`, `tree_linden` and `tree_maple` (`.usdz`).
Each was made by the Meshy service in three steps (a reference picture from the
brief's prompt, a textured 3D model from that picture, a remesh to the brief's
triangle budget) and its section in `docs/asset-brief.md` carries a `Source:` line
with the three task ids, the model name and the date. They are replaced only by a
new sourcing run that updates that line; the generator skips them and
`Scripts/models.sh` checks only that they are present and within budget. The app
turns, sizes and grounds them on load (`SourcedModelFit` and `ModelFit`).

Meshy returned each file with two 2048 x 2048 maps (colour, normal) and two
4096 x 4096 maps (metallic, roughness), 11 to 16 MB a file. They were repacked
locally, with no new Meshy spend: the metallic and roughness maps were flat
(0 and 0.8), so they became constant values on the material; the colour and
normal maps were downscaled to 1024 x 1024; the geometry is untouched. Each file
is now 4 to 5.5 MB. `check.py` refuses any embedded image over 2048 on a side.

Every other file in `Models/` is generated by `bash Scripts/models.sh` from
`Tools/assetgen/` and checked byte-for-byte in CI — never hand-edit a `.usdz`
or a `.png` there; change the generator and re-run.

The three walking characters are not here. They are made with Meshy, not generated, and
live in the sibling folder `Characters/`; `Characters.md` records how each was made.
